# 0003 · 조회할 때 부르지 않고 미리 수집해 DB에 쌓는다 (ETL)

- **상태**: 채택
- **날짜**: 2026-09-11 (2026-11-04 소급 기록)

## 맥락

나라장터 API는 개발계정 기준 서비스별 하루 1,000건 제한이 있고, 페이지 단위로만 준다. 이 서비스의 본질은 "지역별 평균" 같은 집계다.

> 비유: 손님이 주문할 때마다 시장에 다녀오지 않는다. 새벽에 재료를 사서 창고에 쌓아 두고, 주문이 오면 창고에서 꺼내 요리한다.

## 결정

수집기가 API에서 가져와 → 정제해 → PostgreSQL에 저장하고, 조회 API는 DB만 본다. 호출 수가 사용자 수와 무관해지고 `GROUP BY`로 집계가 자유롭다. 나라장터가 점검 중이어도 쌓인 데이터로 동작한다.

세 단계는 모듈로 나눈다. `collector/`는 가져오기만, `transformer/`는 손질만, `repository/`는 저장 · 조회만 한다. "낙찰률이 이상하다"면 Transformer, "데이터가 안 들어온다"면 Collector만 보면 된다. SQL은 `bid_repo.py` 한 곳에 모은다.

## 검토한 대안

- **조회할 때마다 API 호출** — 필터 몇 번이면 한도가 바닥나고, 페이징까지 하면 수 초가 걸리고, 전체 데이터가 없어 집계가 안 되고, 나라장터 장애가 그대로 옮겨 온다.

## 감수할 것

- 실시간성이 없다. 오늘 올라온 공고는 수집한 뒤에야 보인다.
- **최근 기간의 낙찰률은 수의계약에 치우친다.** 경쟁입찰은 개찰이 공고 후 몇 주 뒤라, 같은 기간을 나중에 다시 수집해야 결과가 채워진다 (2026-10-26 실측, `archive/DEVLOG_M1.md`).
- 수집 실패를 추적할 곳이 아직 없다 (`DATA_MODEL` 열린 질문 `fetch_logs`).
