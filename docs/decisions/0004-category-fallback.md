# 0004 · 공종은 대분류 11개, 업종 → 면허 → 키워드 순서로 분류해 컬럼에 저장한다

- **상태**: 채택
- **날짜**: 2026-10-26 (2026-11-04 소급 기록. 저장 여부는 2026-09-12에 결정)

## 맥락

처음 설계는 "`mainCnsttyNm`이 있으면 그대로, 없으면 공고명 키워드"였다. 실제 데이터로 돌려 보니 달랐다.

- `main_cnstty_nm`은 공종이 아니라 **면허 업종 이름 47종**이다. 그대로 쓰면 차트 막대가 47개가 된다.
- 전체의 70%대에서 비어 있어 폴백이 사실상 주 경로다. 공고명 키워드 정확도는 79%, 업종 없는 공고로 다시 재면 71.1%였다.
- 공고명만으로는 90%를 넘기려면 분류율을 크게 버려야 했다(Naive Bayes까지 비교).

## 결정

- 대분류 11개: 건축 · 토목 · 전기 · 통신 · 기계설비 · 소방 · 조경 · 산림 · 환경 · 국가유산 · 기타. 분류 못 하면 NULL, 집계에선 "미분류".
- 순서: **업종(`main_cnstty`) → 면허제한정보의 첫 면허(`license`) → 공고명 키워드(`keyword`) → 분류 못 함(`none`)**. 규칙은 `transformer/category.py`가 원본이다.
- 결과는 `category` · `category_source`에 저장하고, 면허는 원본 그대로 `lcns_lmt_nm`에 저장한다. 규칙을 고치면 `python -m app.reclassify`로 API 호출 없이 다시 분류한다.
- 출처를 숨기지 않는다. 키워드 추정은 화면에 `추정` 배지를 단다 (`DESIGN` 3장).

결과 (2026-10-26, 공고 10,285건): 분류 못 함 10.9% → 1.3%, 업종 없는 공고 중 분류된 것의 예상 정확도 약 96%.

## 검토한 대안

- **조회할 때 계산** — 규칙을 고쳐도 재처리가 없지만 대분류 필터 · `GROUP BY`에 인덱스를 못 쓴다.
- **단어 통계(Naive Bayes)** — 정확도 80.7%로 키워드와 큰 차이가 없고 설명하기 어렵다. 더 나은 원천 데이터(면허)가 있었다.
- **면허 다수결** — "첫 면허"와 일치 수가 같아(27/29) 설명하기 쉬운 쪽을 택했다.

## 감수할 것

- 수집할 때 면허제한정보를 하루 1 ~ 3번 더 호출한다.
- 정확도 96%는 업종 · 면허가 둘 다 있는 공고로 잰 추정치다. 정답지가 경쟁입찰 위주라 수의계약에서는 다를 수 있다.
- 입사 후 실무 분류와 맞는지 다시 본다 (`REQUIREMENTS` 6장).
