# BidWise — 계획

> **목표, 단계와 완료 기준, 진행 현황을 적는 문서다. 진행 상황은 여기에만 쓴다.**
> 겪은 일은 [DEVLOG](DEVLOG.md), 기능 범위는 [REQUIREMENTS](REQUIREMENTS.md). 처음 세운 일정(간트)과 M0 ~ M2의 체크리스트 원본은 [archive/MILESTONES.md](archive/MILESTONES.md).

---

## 1. 목표

공사 입찰 데이터의 수집 → 저장 → 집계 → API → 화면을 끝까지 연결한 대시보드를 완성한다. 처음 목표일(2026-10-19 입사 전)은 지났고 새 일정은 정하지 않았다.

---

## 2. 원칙 — 세로로 먼저, 가로로 나중에

기능을 하나씩 완성하는 게 아니라 **가장 얇은 한 줄기를 끝까지 관통시키는 것**을 우선한다.

```
[나쁜 순서] 수집 전부 완성 → 분석 전부 완성 → 화면 전부 완성
           → 마지막 주까지 눈에 보이는 게 없음

[좋은 순서] 공고 10건만 수집 → DB 저장 → API 1개 → 화면에 숫자 1개 표시
           → 이게 되면 나머지는 살 붙이기
```

M3가 이 관통 지점이다. 완료 기준은 "열심히 했다"가 아니라 "이게 되면 끝"으로 적는다. 막히면 일정을 미루기 전에 범위를 쪼갠다.

## 4. 남은 단계

### M3 — 조회 API + 첫 화면 ★ 관통 지점

> 목표: **브라우저에 실제 데이터가 뜨는 첫 순간을 만든다**

- [ ] FastAPI 프로젝트 구조 세팅 (`main.py`, 라우터 분리)
- [ ] `GET /api/stats/summary` 구현 + Pydantic 응답 스키마
- [ ] `GET /health` 구현 (DB 연결 + 마지막 수집 시각)
- [ ] CORS 설정 (프론트 개발 서버에서 호출 가능하도록)
- [ ] React + TypeScript 프로젝트 생성, shadcn/ui 초기화
- [ ] 디자인 토큰을 CSS 변수로 이식 ([DESIGN](DESIGN.md) 1장)
- [ ] 요약 카드 4개만 구현해 실제 API 데이터 표시

**완료 기준**
```
브라우저에서 로컬 프론트를 열었을 때,
DB에 실제로 들어있는 숫자가 요약 카드 4개에 표시된다.
Swagger(/docs)에서 summary API를 호출해 200 응답을 확인할 수 있다.
```

**시작 전에 정할 것**
- 4번째 카드 "평균 참가업체"가 API · 쿼리에 없다. 쿼리에 더할지 카드를 바꿀지 사전 검증에서 정한다
- 회사 PC에 Python · venv · `.env`가 없다 (2026-11-04 확인). DEVLOG "현재 상태" 참고

수집 → 저장 → 집계 → API → 화면까지 전 구간이 한 번 연결되면, 이후 작업은 이미 연결된 길에 살을 붙이는 것이다.

### M4 — 대시보드 전체 구현

> 목표: Screen 1을 완성한다

- [ ] `GET /api/stats/region` 구현
- [ ] `GET /api/stats/category` 구현 (출처 표현 포함, [ARCHITECTURE](ARCHITECTURE.md) 7장)
- [ ] `GET /api/meta/regions` 구현
- [ ] 한국 GeoJSON 확보 및 ECharts 지도 연동
- [ ] 지역별 낙찰률 코로플레스 (5단계 블루, 구간은 실제 범위 · 분위수)
- [ ] 지역 랭킹 패널 (Progress 컴포넌트)
- [ ] 공종별 막대차트 (Recharts) + 출처 배지
- [ ] 필터바 — 기간 세그먼트 / 지역 · 공종 · 계약방법 Select
- [ ] 필터 변경 시 3개 API 재호출 및 화면 동기화

**완료 기준**
```
필터에서 기간을 바꾸면 요약 카드·지도·차트가 모두 함께 갱신된다.
지도에서 지역별로 색이 다르게 칠해진다.
```

**주의할 지점**
- 필터 변경 시 API 3개가 동시에 나가야 한다 (`Promise.all`)
- `avg_sucsfbid_rate`가 `null`인 지역도 "데이터 없음" 색으로 표시
- GeoJSON의 지역명과 `region_normalized`가 정확히 맞는지 확인. 광주 · 전남은 데이터에서 "전남광주" 하나다 → GeoJSON의 두 영역을 합친다
- 지역별 평균이 90.26 ~ 91.69%에 몰려 있다 (2026-10-26). 고정 5등분하면 전국이 한 색이다

## 6. 일정이 밀릴 때

급할 때 무엇을 버릴지 정해 두지 않으면 정작 중요한 것을 버리게 된다.

| 순위 | 항목 | 판단 |
|---|---|---|
| 1순위로 버림 | 배포 (M6) | 로컬 실행만으로도 프로젝트는 성립 |
| 2순위 | 정렬 기능 (M5) | 리스트가 보이기만 해도 핵심은 충족 |
| 3순위 | 용어 Popover (M5) | 아쉽지만 없어도 기능은 동작 |
| 4순위 | 공종별 차트 (M4) | 지도가 정체성이므로 차트가 후순위 |
| **절대 안 버림** | M0 ~ M3 전 구간 | 여기가 끊기면 프로젝트 자체가 성립하지 않음 |
| **절대 안 버림** | 지도 (M4) | [REQUIREMENTS](REQUIREMENTS.md) 1장의 차별점 |
